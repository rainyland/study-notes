01 先认识树：节点之间的层级关系

树（Tree）是一种非线性数据结构，由一个根节点和若干棵互不相交的子树组成。它强调的是节点之间的一对多层级关系。

图1：树从根节点向下分支。图中 A 是根；D、E、F、G 没有孩子，是叶子节点。
术语含义图中例子

兄弟节点拥有同一个父节点B 与 C；D 与 E
叶子节点没有孩子的节点，度为 0D、E、F、G
内部节点至少有一个孩子的节点A、B、C
节点的度该节点拥有的孩子数A 的度为 2，B 的度为 2
树的度所有节点度数中的最大值本图为 2
别混淆：节点的度数的是“它有几个孩子”；树的度是“整棵树里最大的节点度”。树的根节点没有父节点，除根以外的每个节点有且只有一个父节点。

02 二叉树：每个节点最多两个孩子

二叉树（Binary Tree）是每个节点最多有两个子树的树，并且两个子树有左右之分，不能随意交换。每个节点可能有 0 个、1 个或 2 个孩子。

图2：A 的左孩子是 B，右孩子是 C；B 的左孩子是 D，右孩子是 E。

二叉树的三个基本性质

第 i 层最多有：2i−1 个节点（根为第 1 层）
深度为 k 的二叉树最多有：2k−1 个节点（深度按层数计）
非空二叉树：N0 = N2 + 1

其中，N0 是度为 0 的节点数（叶子数），N2 是度为 2 的节点数。

为什么 N₀ = N₂ + 1？

设二叉树有 N 个节点，则边数为 N−1。另一方面，每个度为 1 的节点贡献 1 条边，每个度为 2 的节点贡献 2 条边：

N−1 = N1 + 2N2，且 N = N0+N1+N2

两式整理后得到 N0=N2+1。也就是说，叶子节点总比“有两个孩子”的节点多 1 个。

例题：一棵二叉树有 8 个度为 2 的节点，那么叶子节点有 8+1=9 个；如果有 12 个叶子节点，度为 2 的节点就是 11 个。

03 满二叉树与完全二叉树：最容易混淆的一组概念

满二叉树

每一层都达到最大节点数，所有叶子都在同一层。

每层全满
完全二叉树

除最后一层外都满；最后一层从左向右连续排列，不能跳空。

最后一层靠左
包含关系：满二叉树一定是完全二叉树；完全二叉树不一定是满二叉树。判断完全二叉树时，重点检查最后一层是否从左向右连续。

深度为 k 的满二叉树

每层节点数依次为 1、2、4、……、2k−1，总数是等比数列求和：

N = 1+2+4+…+2k−1 = 2k−1

例如深度为 4：1+2+4+8=15；深度为 3：1+2+4=7。

完全二叉树的数组编号规律

若从下标 1 开始按层序给节点编号：

关系下标公式例：i=5
父节点⌊i/2⌋2
左孩子2i10
右孩子2i+111
图3：下标 2 的左孩子为 4、右孩子为 5；下标 3 的左孩子为 6、右孩子为 7。

有 n 个节点的完全二叉树，叶子节点数为 ⌈n/2⌉（等价于 ⌊(n+1)/2⌋）。例如 n=10，叶子数为 5；n=15，叶子数为 8。

04 二叉树的四种遍历：先、中、后、层

遍历就是按照某种规则，把树中的节点依次访问一遍。前三种是深度优先遍历（DFS），层序遍历是广度优先遍历（BFS）。

图4：以下四种遍历都使用同一棵树，比较时不要换图。
遍历访问顺序本图结果记忆
前序（先序）根 → 左 → 右A → B → D → E → C根先访问
中序左 → 根 → 右D → B → E → A → C根在中间
后序左 → 右 → 根D → E → B → C → A根最后访问
层序从上到下、从左到右A → B → C → D → E一层一层走
前三种的口诀：前序“根左右”；中序“左根右”；后序“左右根”。先确定根节点什么时候访问，再分别遍历左、右子树。

层序遍历为什么用队列？

队列是先进先出（FIFO）。先把根节点入队，出队访问一个节点，再把它的左、右孩子依次入队；重复直到队列为空。这样就能先访问上一层，再访问下一层。

图5：访问根节点后，把孩子放到队尾，后续按入队顺序访问。

05 树、森林如何转换成二叉树

普通树的一个节点可以有多个孩子，而二叉树最多只有两个孩子。常见转换方式是左孩子—右兄弟表示法：

  • 左指针：指向该节点的第一个孩子。
  • 右指针：指向该节点的下一个兄弟。
图6：A 的左孩子指向第一个孩子 B；B 的右指针指向下一个兄弟 C，C 再指向 D。
最重要的记忆：左边找“第一个孩子”，右边找“下一个兄弟”。右指针不是“第二个孩子”这个固定身份，而是当前节点的下一个兄弟。

森林转换时，树根也按兄弟关系连接

森林由多棵互不相交的树组成。转换时，第一棵树的根作为二叉树根；第二棵树的根成为第一棵树根的右兄弟，第三棵树的根再成为第二棵树根的右兄弟。

图7：三棵树的根 A、B、C 在二叉树中通过右指针串起来。

遍历对应关系

原结构的遍历转换后二叉树的遍历
树的先根遍历二叉树前序遍历
树的后根遍历二叉树中序遍历
森林的先序遍历二叉树前序遍历
森林的中序遍历二叉树中序遍历

06 哈夫曼树：每次合并当前最小的两个权值

哈夫曼树（Huffman Tree）也叫最优二叉树，是带权路径长度 WPL 最小的二叉树。权值越大的叶子，通常会安排得越靠近根；权值小的叶子可以更深。

如何构造哈夫曼树？

  1. 把所有权值看成独立节点。
  2. 选出当前权值最小的两个节点，合并成一个新节点。
  3. 新节点的权值等于两个节点权值之和。
  4. 把新节点放回集合，重复以上步骤，直到只剩一个根节点。
图8：哈夫曼树的构造过程核心是“每轮选当前最小的两个”，新权值放回候选集合。
小心：每次选的是“当前剩余集合中”最小的两个。合并后，新节点也要参与下一轮比较；不是一直挑最初的两个最小权值。

带权路径长度 WPL

路径长度通常按从根到叶子经过的边数计算。只对叶子节点计算：每个叶子的权值乘以它的路径长度，再求和。

WPL = Σ（叶子权值 wi × 根到该叶子的边数 li）

例：叶子权值分别为 3、5，路径长度分别为 2、1，则 WPL=3×2+5×1=11。

哈夫曼树常用结论

考点结论理解方式
节点总数若有 n 个叶子，非叶子节点 n−1，总节点 2n−1每次合并两个节点，新增一个父节点
节点总数奇偶总节点数一定是奇数2n−1 必为奇数
哈夫曼编码前缀编码任何一个字符的编码都不是另一个字符编码的前缀
权值相同不代表叶子一定在同一层位置由每轮合并结果决定
本章题目中的计算：权值（5，6，17，8，19）依次合并：5+6=11；8+11=19；17+19=36；19+36=55。WPL 等于每次合并产生的新权值之和：11+19+36+55=121。

07 二叉搜索树 BST：用大小关系加快查找

二叉搜索树（Binary Search Tree）满足：对任意节点，左子树所有关键字小于该节点，右子树所有关键字大于该节点；左右子树也分别是二叉搜索树（以下按关键字互异讲解）。

图9：左子树值都小于根节点 8，右子树值都大于 8。

查找示例：找 14

  1. 从 8 开始：14 比 8 大，往右。
  2. 到 10：14 比 10 大，继续往右。
  3. 到 14：找到。
口诀：目标值比当前节点小，往左；比当前节点大，往右。查找最小值，就一直沿左孩子走到最左边；查找最大值，就一直沿右孩子走到最右边。

BST 的中序遍历结果是递增序列。注意：普通二叉树的中序遍历不一定有序，只有满足 BST 性质时才有序。

操作平均情况（树较平衡）最坏情况（退化成单支）
查找O(log n)O(n)
插入O(log n)O(n)
删除O(log n)O(n)

树平衡时，每向下一层，候选范围大致减半；树退化成链时，最坏可能要逐个比较 n 个节点。删除节点时还要根据它有 0、1、2 个孩子分别处理；有两个孩子时，常用中序后继或中序前驱替换。

08 存储结构、线性表与复杂度：把相似概念分清

二叉树的两种常见存储

顺序存储

用数组按层序存节点。对完全二叉树尤其方便；若树很稀疏，数组可能浪费空间。

左孩子 2i；右孩子 2i+1
链式存储

每个节点保存数据，以及指向左孩子、右孩子的指针。适合结构变化较多的树。

数据域｜左指针｜右指针
结构别记混：普通单链表节点通常是“数据域 + 指针域”；二叉链表节点通常是“数据域 + 左指针域 + 右指针域”。

顺序表与链表

对比顺序表（顺序存储）链表（链式存储）
内存空间元素连续存放节点不要求连续，用指针连接
按下标访问O(1)，可随机访问O(n)，通常要从头找
中间插入/删除通常要移动后续元素，O(n)已找到前驱后，改指针即可，指针修改本身 O(1)
额外空间通常不需要每个元素额外指针需要保存指针
单链表指针题的前提：若已知插入位置的前驱节点，在中间插入一个新节点通常要改 2 个指针：新节点指向后继，前驱指向新节点。删除一个节点（已知前驱）通常改 1 个指针：前驱直接指向被删节点的后继。若没有给出前驱，寻找位置还要花时间。

逻辑结构与存储结构

逻辑结构：关系是什么
  • 集合：元素之间无特定关系
  • 线性：一对一
  • 树形：一对多
  • 图状：多对多
存储结构：怎么放进内存
  • 顺序存储
  • 链式存储
  • 索引存储
  • 散列存储

树中“父节点 A 与孩子 B、C 的父子关系”属于逻辑结构；链表节点通过指针找到下一个节点，属于存储结构。

时间复杂度常见量级

复杂度直观理解例子
O(1)操作次数不随 n 增长顺序表按下标访问；删除最后一个元素（不考虑额外操作）
O(log n)每一步缩小问题规模平衡 BST 查找
O(n)大致遍历一遍顺序查找、遍历链表
O(n²)两层规模为 n 的循环简单双重循环

例如执行次数为 3n²+5n+2，只保留增长最快的最高阶项，忽略常数系数与低阶项，因此是 O(n²)。

算法与抽象数据类型 ADT

  • 算法五个基本特征：有穷性、确定性、可行性、输入、输出。输入可以为零个或多个；输出至少有一个。
  • ADT：描述数据的逻辑特性以及允许进行的操作，不规定具体实现。比如栈规定入栈、出栈、取栈顶；底层可以用数组，也可以用链表。

遍历口诀

前序：根左右　　中序：左根右　　后序：左右根　　层序：逐层从左到右

左孩子右兄弟：左指针找第一个孩子；右指针找下一个兄弟。

本章原题里需要特别谨慎的表述

第 2 题更正：树的度为 4，度为 1、2、3、4 的节点数分别为 4、2、1、1。叶子数应为 8（D），不是 7。用边数核算：总边数=1×4+2×2+3×1+4×1=15；总节点数=叶子数+8；树的边数=总节点数−1，所以叶子数+7=15，叶子数=8。请以这里的推导为准。
第 12 题题干有歧义：“哪种遍历是深度优先遍历”时，前序和中序（后序也属于 DFS）都符合；如果选项只允许一个答案，题目本身不严谨，不能硬记成只有前序。
第 32、34 题表述不够严谨：只有一个左孩子并不能推出“适合某一种唯一遍历方法”；链式存储也不只适用于某一种逻辑结构。遇到这类填空，先看老师讲义或标准答案的具体语境，不要把模糊题干当成普遍定理。
其他常见判断陷阱：
  • 普通二叉树中序遍历不一定有序；BST 的中序遍历才递增。
  • 先序访问根在最前；后序访问根在最后。
  • 哈夫曼编码是前缀编码；权值相同的叶子不一定同层。
  • 树不必先转换成二叉树才能存储；还可以用双亲表示法、孩子表示法等。
  • 先序和后序序列通常不能唯一确定一棵二叉树。
  • 树转换成左孩子右兄弟二叉树后，叶子节点数量不一定保持不变。

10 最后，用 6 道小题检查自己

先自己作答，再点开“查看解析”。这些题覆盖本章最核心的公式和概念。

1. 二叉树有 7 个度为 2 的节点，叶子节点有几个？

答案：8 个。 N₀=N₂+1=7+1。

2. 深度为 4 的满二叉树有多少个节点？

答案：15 个。 2⁴−1=15；也可逐层相加 1+2+4+8。

3. 对一棵二叉树，后序遍历的访问顺序是什么？

答案：左子树 → 右子树 → 根节点。 口诀“左右根”。

4. 哈夫曼树每一轮选择哪两个节点合并？

答案：当前权值最小的两个节点。 合并后将新节点权值放回集合。

5. 完全二叉树有 20 个节点，叶子节点有几个？

答案：10 个。 ⌈20/2⌉=10。

6. BST 查找最小值，应该沿哪个方向走？

答案：一直沿左孩子走，直到没有左孩子。

先理解树的层级关系 → 掌握二叉树定义和性质 → 分清满二叉树与完全二叉树 → 会写四种遍历 → 理解树/森林转换 → 会构造哈夫曼树并计算 WPL → 掌握 BST 查找 → 最后区分存储结构、逻辑结构和时间复杂度。
