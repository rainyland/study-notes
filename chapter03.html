栈和队列：把“先进后出、先进先出”真正学明白

01 栈：只能从栈顶进出

栈（Stack）是一种只允许在同一端进行插入和删除的线性表。这一端叫栈顶（top），另一端叫栈底（bottom）。

入栈 Push

新元素放到栈顶。

出栈 Pop

只能取走当前栈顶元素。

一句话记忆：栈 = 后进先出（LIFO）。最后进入的元素，最先离开。

栈的基本操作

操作含义注意
InitStack初始化空栈建立空栈
Push入栈先检查栈是否已满，再放入栈顶
Pop出栈先检查栈是否为空，再移除栈顶
GetTop读取栈顶只读取，不删除
StackEmpty判断是否为空空栈不能出栈

栈和队列都属于受限的线性表：它们不是普通线性表那样任意位置都能插入、删除，而是限制了操作端点。

02 栈的顺序存储与共享栈

顺序栈：用数组保存元素

假设数组为 V[1...n]，并且初始栈顶指针 top=n+1。这代表栈从数组右侧向左增长。

本题给定的存储约定是从右向左入栈，别和从左向右的常见写法混淆。
入栈：top = top − 1；V[top] = x

例如初始 top=6，第一次入栈先让 top 变成 5，再把元素写入 V[5]。

共享栈：两个栈共用一个数组

两个栈的栈底分别放在数组两端，栈1向右长，栈2向左长。这样一边空闲的空间可以被另一边使用。

状态条件
栈1为空top[1] = 0
栈2为空top[2] = n+1
共享栈满top[1] + 1 = top[2]
判断共享栈满：只要两个栈顶中间已经没有空位，就满了。不是某一个栈先碰到数组末尾。

03 合法出栈序列：画栈，不要靠猜

给定入栈顺序 1,2,3。每次只能把下一个元素入栈，也只能弹出当前栈顶。问哪些出栈顺序可能出现？

核心判断：如果想让 2 先出栈，但 3 已经入栈且压在 2 上面，那么必须先弹出 3；不能跳过栈顶直接取 2。

04 队列：一端进、另一端出

队列（Queue）是一种只允许在队尾插入、在队头删除的线性表。

队头负责删除，队尾负责插入；元素按进入队列的先后顺序离开。
一句话记忆：队列 = 先进先出（FIFO）。先进入的元素，先离开。
操作位置含义
EnQueue队尾 rear新元素进入队列
DeQueue队头 front删除最早进入的元素
GetHead队头 front读取队头但不删除

栈与队列的共同点：都属于特殊线性表，插入和删除都受端点限制。不同点是栈在同一端操作，队列在两端分别操作。

05 循环队列：解决“假溢出”

为什么需要循环队列？

普通顺序队列中，前面元素出队后，前面的数组位置虽然空出来了，但 rear 仍可能已经走到数组末尾。此时如果不能继续利用前面的空位，就会出现假溢出。

循环队列的核心公式

循环队列把数组看成一个首尾相连的圆环。指针走到最后一个位置，再前进一步就回到 0。

rear = (rear + 1) % MAXSIZE
示意：MAXSIZE=8 时，位置 7 再前进一步回到位置 0。
判断条件含义
队空front == rear队头指针和队尾指针重合
队满(rear + 1) % MAXSIZE == front再放一个元素就会追上 front
当前元素个数(rear - front + MAXSIZE) % MAXSIZErear 指向下一次入队位置
为什么通常浪费一个存储单元？为了区分“队空”和“队满”。两者都可能表现为 front 与 rear 重合，因此约定空队列 front=rear；队满时让 rear 的下一个位置等于 front，留出一个空位。

用 MAXSIZE=5 走一遍

例子：数组下标为 0、1、2、3、4。rear=4 时，再入队会回到 0。

数组位置

front=2，rear=1

判断结果

点击按钮查看队列状态。

队满判断：(rear+1)%5 是否等于 front

下标范围提醒：如果题目数组写成 A[0...m]，共有 m+1 个位置，取模应使用 m+1；如果数组长度直接记作 MAXSIZE，就使用 MAXSIZE。看清楚题目给的数组范围。

06 链式队列与删除操作

链式队列用结点链接元素，通常设置两个指针：front 指向队头，rear 指向队尾。

  • 队列有多个结点时，删除队头：通常只需要修改 front。
  • 队列只有一个结点时，删除后队列变空：front 和 rear 都需要调整为空状态。
考试表述：链式队列删除时，头、尾指针可能都要修改。因此选择“可能都要修改”，而不是“始终都修改”。

07 递归为什么离不开栈

递归是函数在执行过程中调用自身。每次调用都需要暂存本次调用的参数、局部变量和返回位置；这些信息要按“后调用的先返回”的顺序管理，因此使用栈。

A 调用 B，B 调用 C；C 完成后先返回 B，再返回 A。

递归算法必须具备两部分

终止条件

告诉程序什么时候停止继续调用自己，避免无限递归。

递归部分

把当前问题转化成规模更小、形式相同的子问题。

易错：递归不代表效率一定高。递归调用会产生额外的调用栈开销；某些问题用循环实现可能更省空间。

栈常见应用：递归调用、子程序调用、表达式求值、括号匹配、深度优先搜索等。

08 中缀表达式转后缀表达式

中缀表达式是我们平时熟悉的写法，例如 a+b；后缀表达式把运算符放在操作数后面，例如 ab+。转换时通常借助一个运算符栈。

中缀表达式
a + b × c

运算符写在操作数中间。

后缀表达式
a b c × +

运算符写在对应操作数后面。

转换规则：记住这四条

  1. 操作数（字母、数字）：直接加入输出，不进运算符栈。
  2. 左括号 (：直接入栈，作为括号内外的分界。
  3. 遇到运算符：若栈顶运算符优先级更高或相同，先弹出栈顶到输出；再把当前运算符入栈。左括号会阻止继续弹出。
  4. 遇到右括号 )：不断弹出运算符到输出，直到遇到左括号；左括号丢弃，不输出。
运算符优先级说明
*、/高乘除先于加减
+、-低同级运算从左向右
(括号屏障阻止括号外运算符参与比较
最关键的判断：栈顶是 +，新遇到 *：新运算符优先级更高，直接压入。栈顶是 *，新遇到 +：先弹出 *，再处理 +。

例1：a+b*c

结果：a+b*c → abc*+。乘法先算，所以 * 在后缀表达式中先于 + 出现。

例2：a*(b+c)

括号里的 b+c 必须先完成，转换结果为：

a*(b+c) → abc+*
